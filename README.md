  <p>Hyprland</p>

`hyprland/config/` contains the Hyprland 0.57 Lua configuration. The entry point
loads modules for monitors, startup/environment, appearance, input, application
commands, keybindings, and window rules. Edit these repository files, then install:

```bash
./hyprland/manage install
./hyprland/manage check
```

The helper runs on the host when invoked from a container. It validates the
configuration with `Hyprland --verify-config`, stages it alongside the installed
directory, and saves the entire previous `~/.config/hypr/` directory under
`~/.local/state/dotfiles/hyprland/backups/`. Unrelated files in that directory are
preserved during installation. A matching installation is a no-op. It reloads
the running session and restores the previous files if that reload reports an
error. It does not restart Hyprland or install packages. XDG configuration and
state directory overrides are supported.

List backups or restore the most recent pre-install snapshot:

```bash
./hyprland/manage backups
./hyprland/manage rollback
# Restore a specific snapshot using the ID printed by backups:
./hyprland/manage rollback BACKUP_ID
```

Restoring also backs up the configuration it replaces. Backups are local and are
not committed. Rollback restores the whole configuration directory to its saved
state, including unrelated files. No command prunes backups automatically.

The current monitor module matches the OMEN and Dell by description, with the
1080p Dell at approximately 75 Hz centered above the 1440p OMEN at approximately 165 Hz, both
at scale 1. Other monitors use their preferred mode with automatic placement.
Black 16 px corner masks round the top of the uppermost display and the bottom
of the lowermost display, including fullscreen windows. The edges between the
stacked displays stay square; the masks pass clicks through and reserve no space.
UWSM remains the session manager. The startup module creates systemd user
services for text and image clipboard history and removable-drive automounting. These services restart on failure
and stop with `graphical-session.target`. Installing reconciles the services;
reloading the Lua config alone does not launch duplicate processes. A rollback
to the initial configuration stops the added automount, clipboard, shell, capture, and idle services.
Appearance retains the packaged defaults, with the autogenerated-config notice
disabled. The package plan is in [hyprland-packages.md](hyprland-packages.md).

`dotfiles-hyprland-automount.service` replaces GNOME Shell's removable-media
automount policy using GIO/GVfs and UDisks2. It handles eligible local volumes at
login and when inserted, honors `org.gnome.desktop.media-handling automount`, and
pauses while the logind session is inactive or locked. Mounted volumes, internal
volumes not marked for automount, and network shares are left alone. Disconnecting
a drive cancels its pending mount; stopping the service never unmounts drives.
Explicitly unmounted volumes stay unmounted until removed and reinserted.
Newly mounted folders open only when `automount-open` is enabled and
`autorun-never` is disabled; no software autorun is implemented. Encrypted drives
requiring a password must be unlocked in Files. Safely eject drives from Files.
Inspect logs with `journalctl --user -u dotfiles-hyprland-automount.service`.
`~/.config/hypr/bin/dotfiles-desktop desktop automount --check` reports policy and
visible volumes without mounting anything; run it from the Hyprland session.
PrusaSlicer's bundled GTK chooser also needs the GVfs permissions in
`_scripts/load`; apps using the file chooser portal use the host's volume view.

`dotfiles-hyprland-agents.service` registers Bluetooth pairing and NetworkManager
credential agents after the pill shell is ready. Pairing codes, PIN entry,
Wi-Fi/enterprise credentials, and supported VPN password/token requests use the
same expanding pill surface as portal dialogs. Cancel, Escape, service shutdown,
and session locking dismiss pending requests. Password inputs are masked and
cleared on close; their values travel over a local socket, never request files
or command-line arguments. Agent-owned secrets may be saved through `secret-tool`
to the existing Secret Service according to the connection's secret flags and
the Remember choice. VPN plugins exposing external UI descriptors are rendered
in the pill; provider-specific browser/SSO flows still require their own client.
Inspect registration with `journalctl --user -u dotfiles-hyprland-agents.service`.

The custom desktop backend is Rust, built from `hyprland/native/`. QML and
JavaScript own presentation, input, and animation; Lua owns compositor policy.
The installer builds with the locked Cargo dependencies in the development
container and installs `~/.config/hypr/bin/dotfiles-desktop` alongside the config.
The sharing picker and Brevlada email bridge are native multicall executables
from the same build. Normal desktop operations and maintenance commands no longer
invoke Python. Rollback to a historical configuration can restore the Python
entry points bundled with that configuration.

Build caches stay under `${XDG_CACHE_HOME:-~/.cache}/dotfiles-build/hyprland-native/`.
The binary is part of the configuration snapshot, so rollback restores matching
QML, Lua, and Rust code. Known retired Python helpers are removed from the
installation; unrelated user scripts are preserved.
See [the runtime architecture and development commands](hyprland/native/README.md).

Portal preferences live in `xdg-desktop-portal/hyprland-portals.conf`. Install
with `./xdg-desktop-portal/manage install` and verify with
`./xdg-desktop-portal/manage check`. File selection uses Nautilus through the
GNOME portal backend. The custom `dotfiles` backend supplies Open With and
permission dialogs in Quickshell, using the existing shell theme. Hyprland
retains screen capture and PipeWire streaming, with a custom source picker for
monitors, windows, workspaces, and monitor regions. Printing retains the GTK
backend. GNOME sessions continue using their own portal preferences.

Dotfiles builds its own portal frontend release, `1.22.1+dotfiles.1`, from the
exact upstream revision and patches in `xdg-desktop-portal/frontend-release.json`.
It includes the upstream [peer-disconnect deadlock fix](https://github.com/flatpak/xdg-desktop-portal/pull/2108)
for the [file-manager startup stall](https://github.com/flatpak/xdg-desktop-portal/issues/2093).
`./xdg-desktop-portal/manage install` builds a missing or changed release in the
development Toolbox, installs it, and activates it; `_scripts/load` runs that
installer too. `./xdg-desktop-portal/build-frontend` explicitly rebuilds it, and
`./xdg-desktop-portal/build-frontend --check` verifies the installed artifact.

Source and build caches live under `~/.cache/dotfiles-build/xdg-desktop-portal/`,
keyed by the source, patches, and build options. Modified cached source is
preserved and rejected. Versioned binaries and build receipts live under
`~/.local/libexec/dotfiles/portal-releases/`. Receipts record the recipe and binary
checksum; `manage check` also verifies that the running service uses that binary.
The service override is
`~/.config/systemd/user/xdg-desktop-portal.service.d/90-peer-disconnect.conf`.
It applies across desktop sessions and continues selecting our pinned release
after system updates. The Fedora frontend and its helper services remain
installed. Update the release manifest and patches to change our release;
remove the override and reload/restart the user service to return to Fedora's
frontend. Previous versioned binaries remain available for rollback.

Email links resolve to Brevlada. The installed `brevlada-email` bridge forwards
attachments through Flatpak's document portal. Unknown file types without
suggested applications offer installed file handlers in Open With, rather than
an empty list. The installer removes the old catch-all Code association for
unknown binary files and preserves other file preferences.

Open With uses the app launcher's dimensions, search field, and shared result
rows. Type to filter, use Up/Down to select, and press Enter or click a row to
open. Escape cancels the request, including when the search has no matches.
In the running Hyprland shell it expands from the existing pill and collapses
back on selection or cancellation. Permission prompts and the screen-sharing
picker use that same pill expansion and collapse, with their existing choices,
previews, sharing tabs, remember option, and region selection. These dialogs
share one view with the standalone fallback. Requests pass over the private
runtime socket `dotfiles-portal-shell.sock`; request updates and frontend Close
are reflected in that same pane. Other desktops and unavailable or busy shells
retain the standalone dialog.

The installer preserves unrelated Hyprland rules and `xdph.conf` settings,
backs up every changed file under `~/.local/state/dotfiles/xdg-desktop-portal/`,
and restores files if activation or reload fails. It refuses installation during
an active Hyprland portal session because reloading that backend would interrupt
sharing. The `dotfiles-portal.service` user service starts through D-Bus activation
and stops with the graphical session. Inspect its logs with
`journalctl --user -u dotfiles-portal.service`. Standalone fallback dialogs float
at the center of the screen; foreign-window transient parenting is not yet
implemented. File selection and printing retain their native backend dialogs. Applications with their own dialogs bypass these portal UIs.

Sharing previews use live screencopy when available and a muted window outline
when it is unavailable. Workspace cards compose the current window layout from
Hyprland metadata, with live window previews when available. Window previews
require an unambiguous application/title match; actual sharing always uses the
exact source ID supplied by XDPH. Dialogs use compact controls and brief
entrance, selection, and tab transitions; permission details expand on demand.

Brightness, volume, and microphone feedback appears for 1.6 seconds in a compact
pill with the level bar and, when there are unread notifications, the notification
dot. It also appears when the idle pill is hidden in fullscreen or disabled.
Brightness levels are read back from the monitor, which requires DDC/CI to be
enabled on the display.

Each monitor has an independent dynamic workspace list and an empty workspace
at both ends. Opening a window at either edge adds another empty workspace on
that side; visiting an empty edge does not add more. An entirely empty monitor
keeps a single workspace. Other empty
workspaces disappear automatically after leaving them. Switching stops at the
ends of the list. Number shortcuts refer to positions within the focused
monitor's list. If no positive ID is free before the first workspace, only the
affected monitor's workspace IDs shift to make room; windows, layouts, and focus
stay on their existing workspace objects.

The Quickshell launcher indexes installed desktop entries, including Flatpaks,
with fuzzy subsequence matching and frequently used apps ranked ahead of equally
relevant matches. App-title matches precede provider results, with name prefixes
ranked first; description-only matches follow the other providers. For example, type `Tele` and
Enter to launch Telegram, or `trm` to match Terminal. UWSM launches the chosen desktop entry.
Arithmetic such as `12 * (3 + 4)` shows a Qalculate result; Enter copies it.
Qalculate handles arithmetic, functions, units, currencies, and incomplete
parentheses without launching a calculator window. The same pill
also searches characters, Zen bookmarks, and indexed files. Ordinary text
searches across providers; optional prefixes narrow the search. Launcher usage
counts are stored in `$XDG_STATE_HOME/dotfiles/hyprland/launcher-usage.json`.
The application index is shared across openings and refreshes after a minute. Choosing an app closes it
immediately while the app starts independently.

Enter opens an app, file, bookmark, or web search, or copies a computed result.
Results use the same typography as the rest of the shell, without filter tabs
or an action footer. Ctrl+C copies the result when no input text is selected,
Ctrl+D toggles a favorite, Ctrl+Enter reveals a file in Nautilus, and Tab browses
the selected folder. Clear the query to see favorites and recent items. Favorites
and up to 100 recent entries persist in
`$XDG_STATE_HOME/dotfiles/hyprland/launcher.json`. Date and currency entries refresh when shown again. English/Russian
keyboard-position correction supplements app, character, bookmark, and file
matching without changing the typed query or keyboard layout.
Ordinary character search combines text/emoji presentation variants into one
row; explicit character searches and code-point lookups retain exact variants.

The provider worker starts on demand, keeps local catalogs in memory, debounces
queries, discards obsolete results, and exits after two minutes with the
launcher closed. Application matching stays inside QML; all calculation uses
the native Qalculate engine through its bounded `qalc` command. A small input
adapter supplies currency units for unlabelled additive amounts, leaving
multipliers, divisors, percentages, and physical unit algebra to Qalculate. File
search reuses Nautilus's `org.gnome.Shell.SearchProvider2` interface and the
existing GNOME LocalSearch index, respecting its indexed folders and exclusions.
It does not build another file index. Directory completion reads only the
specified directory. Emoji and Unicode names reuse installed IBus catalogs;
their derived cache lives in `$XDG_CACHE_HOME/dotfiles/hyprland/`.

Zen bookmarks are read from a private snapshot of the active installation's
default profile, including its SQLite WAL, without changing browser data.
Bookmarks open as new tabs in that profile. Web searches pass the query to Zen
so its own configured engine handles it; browser tab search is not enabled.
Qalculate refreshes cached exchange rates at most daily in the background and
shows their date with every conversion. Offline use keeps the dated cached
rates. ECB reference rates are published on working days, so weekends retain
the latest working day’s date. The native `qalc` executable is preferred. On this Silverblue install,
the package is staged and an unmodified user-local RPM payload under
`~/.local/lib/dotfiles/qalculate/` supplies it until the system executable is
available. Bubblewrap gives that fallback its packaged data directory without
changing the running system's packages.

The capture overlay freezes every monitor and uses one desktop-wide selection,
including regions spanning displays with different scale factors or negative
coordinates. The brown-glass toolbar appears after mouse release and stays
hidden on every monitor during a drag. It tries below the selected area, above,
left, right, then inside its top edge. Horizontal placements center on the
selection; side placements use an upright vertical toolbar centered alongside
it. Placement stays within the hosting monitor. Screenshots offer Pen, Arrow,
Box, Text, Blur, and a cursor toggle. Recordings offer cursor, speaker, and mic
toggles, an FPS button, and Start recording. Click the selected annotation tool again to turn it off. With no
tool selected, left-drag inside the selection to move it. Left-drag outside it
to select a new region; right-drag anywhere always selects a new region, even
with an annotation tool active. Movement keeps the region inside desktop bounds.
The opacity icon applies heavy blur with 8px rounded corners, including earlier
annotations; later annotations remain sharp. Backspace/Delete undo each blur patch.
There are no selection, copy/save, undo, or close buttons. Escape cancels.
Outside text entry, every key (including modifiers and non-Latin layouts) copies
and saves a screenshot except Escape, which cancels, and Backspace/Delete, which
undo annotations. Text entry retains its normal
editing and clipboard behavior; Enter commits a label. The image is copied to
the clipboard and saved as PNG under the XDG Pictures directory's `Screenshots/`.
Selection borders, dimming, and controls are excluded. Mixed-scale captures use
the highest participating output scale; gaps between monitors are black.
Screenshot and recording regions are remembered separately, together with the
shared cursor setting, recording audio toggles, and recording frame rate, under
`~/.local/state/dotfiles/hyprland/capture.json`.
Restored regions are clipped to the currently connected desktop.

Alt+Print captures the active window directly. It rounds the corners to a 10 px
radius, adds 24 px of white padding on each side, and copies and saves the PNG.
For recording, choose a region, cursor option, and audio sources, then press any key except Escape/Backspace/Delete
or the video-camera button. Ctrl+Shift+Alt+R is the only stop control. Recording
borders remain outside the encoded rectangle; dimming passes input through.
The speaker and mic buttons are independent and initially off. They use the
default speaker output's monitor and default microphone when recording starts.
Enabling both mixes them into one normalized audio track using FFmpeg's live
audio input, without creating virtual devices or changing audio routing.
Audio choices apply to both single-display and spanning recordings.
The FPS button cycles 60 → 120 → 144 → 165 → 60 and remembers the selected rate.
It limits each display recorder and sets the final spanning composition's frame
rate. Capture remains damage-driven; actual frame rate depends on display
updates, refresh rate, and encoder capacity.
Single-output regions retain direct wl-screenrec capture. Spanning regions
record each intersecting output, then crop, scale, and combine them into one MP4
in the XDG Videos directory's `Recordings/` when stopped. This final composition
can take additional time. Capture overlays disappear as soon as stopping begins.
Final composition prefers VA-API hardware decoding, cropping/scaling, overlay,
and encoding, without downloading video frames to the CPU. It tries the available
DRM render nodes, preferring H.264 for normal dimensions and HEVC above 4096
pixels in either dimension. Unsupported codecs, dimensions, or drivers fall back
to software composition with four encoder threads. Audio remains a single AAC
track with its original recording offset. The complete MP4 is published atomically;
failed attempts do not replace an existing video or leave a partial final file.
The join's shared attempt deadline scales with recording duration, from five
minutes up to one hour, so long recordings have time to finish.
Intermediate clips are retained next to the output if composition fails.
FFmpeg with VA-API decoding, `scale_vaapi`/`overlay_vaapi`, and hardware H.264/HEVC
encoders enables the accelerated join. Keep libx264 installed for software
recovery. Recording audio requires `pactl`, PipeWire-Pulse, and FFmpeg's Pulse
input; mixing both sources also uses its `lavfi` input and `amovie`/`amix` filters.

The selector keeps input captured until held keys and modifiers are released,
so cancellation/export does not reach the restored app. It suspends shell
focus-loss dismissal while open, preserving an open launcher and its query and
selection. Startup uses parallel raw pixmaps and a preloaded worker with its
graphics context and per-monitor controls prepared at login. Idle surfaces stay
full-size and transparent with empty input regions and no keyboard focus,
keeping rendering resources ready without a startup resize flash. Frozen images share
decoded pixels across the overlay, selection, and blur layers. Direct local
sockets avoid launching IPC clients for opening the selector and suspending
shell focus dismissal; older workers and standalone use retain the IPC/cold
fallbacks.

Super+Shift+V opens clipboard history beside the text caret or, when caret
coordinates are unavailable, near the pointer. Click an item or select it with
the arrow keys and press Enter to paste it into the original app. The list
shows color swatches, links, formatted HTML, and image and video thumbnails.
Clipboard history preserves the original formats, skips selections marked
sensitive, and includes older Cliphist entries. The floating clear button
empties the history. A visible standalone image tag can load a remote thumbnail.
On paste the picker offers the image and supplies the URL to text-only apps.

The lock screen has an opaque background, password entry, and clock on each
display. **Automatic locking is disabled by preference.** There are no idle
timers or automatic lock-on-sleep hooks. Super+L and the power menu provide
manual locking. Startup stops the legacy idle service even if an old lock
verification marker remains.

<h2 align="center">
  <p>System sleep</p>
</h2>

`services/sleep/` restricts normal systemd suspend to deep (S3) sleep using
`SuspendState=mem` and `MemorySleepMode=deep`. If that attempt fails, systemd
stops instead of trying the `freeze` / `s2idle` fallback. Requires systemd 256+
and hardware with deep sleep support; this is the configuration for the
TUF GAMING B650-PLUS desktop with AMD graphics.

The Logi Bolt receiver (`046d:c548`) cannot wake the PC from suspend. A udev
rule applies this when it is connected, and a suspend pre-hook reapplies it
before every sleep. This targets the only wake-enabled USB device behind the
GP17 bridge that reported IRQ 30 after a five-second S3 sleep on November 16,
2026. The logs identify the bridge; the receiver is the suspected downstream
source. Normal receiver input still works while awake. Use the power button
to wake the PC.

On October 6, 2026, a pending wake event interrupted deep sleep. Both GPUs
recovered from that attempt, but the immediate `s2idle` fallback was rejected
by the integrated GPU and left the dedicated Radeon wedged. The original wake
device was not recorded. This configuration removes that fallback; it does not
guarantee recovery from every possible GPU or firmware fault.

The suspend service also enables kernel power-management debug messages and
records wake IRQ information, wake-source counters, suspend statistics, interrupt
mapping, and USB / ACPI wake settings before and after each attempt. Diagnostics
are saved in the system journal, time-limited to five seconds per hook, and
cannot block sleep on failure. Kernel PM debug messages remain enabled until
reboot (or until `/sys/power/pm_debug_messages` is set back to `0`).

<h3 align="center">
  <p>Usage</p>
</h3>

From the repository root:

```bash
./services/sleep/manage install
```

The helper installs configuration under `/etc/systemd/`, helpers under
`/usr/local/sbin/`, and the receiver rule under `/etc/udev/rules.d/`. It restores
SELinux labels, reloads systemd and udev, and disables receiver wake immediately.
It takes effect on the next sleep attempt without rebooting.
When run from Distrobox, it executes on the host and requests administrator
authentication there. Installation does not trigger sleep.

`_scripts/load` includes this installation. `_scripts/dump` calls
`./services/sleep/manage dump` to save the installed host files back to the repo.

After the next sleep attempt, inspect these logs on the host (use `-b -1`
instead of `-b` if you have rebooted since the attempt):

```bash
journalctl -b -u systemd-suspend.service
journalctl -b -k -g 'PM:|Wakeup|wakeup|amdgpu'
```

To remove this configuration, run on the host:

```bash
sudo rm /etc/systemd/sleep.conf.d/90-deep-only.conf \
    /etc/systemd/system/systemd-suspend.service.d/90-wake-diagnostics.conf \
    /usr/local/sbin/sleep-wake-diagnostics \
    /usr/local/sbin/sleep-disable-receiver-wake \
    /etc/udev/rules.d/99-logi-bolt-no-wake.rules
sudo systemctl daemon-reload
sudo udevadm control --reload-rules
echo 0 | sudo tee /sys/power/pm_debug_messages
```
