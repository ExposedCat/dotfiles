`hyprland/config/` contains the Hyprland 0.57 Lua configuration. The entry point
loads modules for monitors, startup/environment, appearance, input, application
commands, keybindings, and window rules. Edit these repository files, then install:

```bash
./hyprland/manage install
./hyprland/manage check
```

The helper runs on the host when invoked from a container. It validates the
configuration with `Hyprland --verify-config`, stages it alongside the installed
directory, and saves the entire previous `~/.config/hypr/` directory under
`~/.local/state/dotfiles/hyprland/backups/`. Unrelated files in that directory are
preserved during installation. A matching installation is a no-op. It reloads
the running session and restores the previous files if that reload reports an
error. It does not restart Hyprland or install packages. XDG configuration and
state directory overrides are supported.

List backups or restore the most recent pre-install snapshot:

```bash
./hyprland/manage backups
./hyprland/manage rollback
# Restore a specific snapshot using the ID printed by backups:
./hyprland/manage rollback BACKUP_ID
```

Restoring also backs up the configuration it replaces. Backups are local and are
not committed. Rollback restores the whole configuration directory to its saved
state, including unrelated files. No command prunes backups automatically.

The current monitor module matches the OMEN and Dell by description, with the
1080p Dell at approximately 75 Hz centered above the 1440p OMEN at approximately 165 Hz, both
at scale 1. Other monitors use their preferred mode with automatic placement.
Black 16 px corner masks round the top of the uppermost display and the bottom
of the lowermost display, including fullscreen windows. The edges between the
stacked displays stay square; the masks pass clicks through and reserve no space.
UWSM remains the session manager. The startup module creates systemd user
services for text and image clipboard history. These services restart on failure
and stop with `graphical-session.target`. Installing reconciles the services;
reloading the Lua config alone does not launch duplicate processes. A rollback
to the initial configuration stops the added clipboard, shell, capture, and idle services.
Appearance retains the packaged defaults, with the autogenerated-config notice
disabled. The package plan is in [hyprland-packages.md](hyprland-packages.md).

Portal preferences live in `xdg-desktop-portal/hyprland-portals.conf`. Install
with `./xdg-desktop-portal/manage install` and verify with
`./xdg-desktop-portal/manage check`. File selection uses Nautilus through the
GNOME portal backend. The custom `dotfiles` backend supplies Open With and
permission dialogs in Quickshell, using the existing shell theme. Hyprland
retains screen capture and PipeWire streaming, with a custom source picker for
monitors, windows, workspaces, and monitor regions. Printing retains the GTK
backend. GNOME sessions continue using their own portal preferences.

The installer preserves unrelated Hyprland rules and `xdph.conf` settings,
backs up every changed file under `~/.local/state/dotfiles/xdg-desktop-portal/`,
and restores files if activation or reload fails. It refuses installation during
an active Hyprland portal session because reloading that backend would interrupt
sharing. The `dotfiles-portal.service` user service starts through D-Bus activation
and stops with the graphical session. Inspect its logs with
`journalctl --user -u dotfiles-portal.service`. Custom dialogs float independently
at the center of the screen; foreign-window transient parenting is not yet
implemented. Applications with their own dialogs bypass these portal UIs.

Protocol checks run with:

```bash
python3 -m unittest discover -s hyprland/tests -p test_portals.py
```

Sharing previews use live screencopy when available and a muted window outline
when it is unavailable. Workspace cards compose the current window layout from
Hyprland metadata, with live window previews when available. Window previews
require an unambiguous application/title match; actual sharing always uses the
exact source ID supplied by XDPH. Dialogs use compact controls and brief
entrance, selection, and tab transitions; permission details expand on demand.
Private X11
checks cover dialog behavior and protocol responses, not live Wayland/PipeWire
capture or GPU performance.

The brightness feedback appears inside the main pill with the adjusted output name, percentage,
and level bar, then hides after 1.6 seconds. It shares the volume/microphone OSD,
so the latest control replaces the previous one. Levels are read back from the
monitor; DDC/CI must be enabled on the display.

Each monitor has an independent dynamic workspace list and an empty workspace
at the end. Opening a window there adds another empty workspace. Other empty
workspaces disappear automatically after leaving them. Switching stops at the
ends of the list. Workspace IDs remain stable while windows are open; number
shortcuts refer to positions within the focused monitor's list.

The Quickshell launcher indexes installed desktop entries, including Flatpaks,
with fuzzy subsequence matching and frequently used apps ranked ahead of equally
relevant matches. App-title matches precede provider results, with name prefixes
ranked first; description-only matches follow the other providers. For example, type `Tele` and
Enter to launch Telegram, or `trm` to match Terminal. UWSM launches the chosen desktop entry.
Arithmetic such as `12 * (3 + 4)` shows a Qalculate result; Enter copies it.
Qalculate handles arithmetic, functions, units, currencies, and incomplete
parentheses without launching a calculator window. The same pill
also searches characters, Zen bookmarks, and indexed files. Ordinary text
searches across providers; optional prefixes narrow the search. Launcher usage
counts are stored in `$XDG_STATE_HOME/dotfiles/hyprland/launcher-usage.json`.
The application index is shared across openings and refreshes after a minute. Choosing an app closes it
immediately while the app starts independently.

Enter opens an app, file, bookmark, or web search, or copies a computed result.
Results use the same typography as the rest of the shell, without filter tabs
or an action footer. Ctrl+C copies the result when no input text is selected,
Ctrl+D toggles a favorite, Ctrl+Enter reveals a file in Nautilus, and Tab browses
the selected folder. Clear the query to see favorites and recent items. Favorites
and up to 100 recent entries persist in
`$XDG_STATE_HOME/dotfiles/hyprland/launcher.json`. Date and currency entries refresh when shown again. English/Russian
keyboard-position correction supplements app, character, bookmark, and file
matching without changing the typed query or keyboard layout.
Ordinary character search combines text/emoji presentation variants into one
row; explicit character searches and code-point lookups retain exact variants.

The provider worker starts on demand, keeps local catalogs in memory, debounces
queries, discards obsolete results, and exits after two minutes with the
launcher closed. Application matching stays inside QML; all calculation uses
the native Qalculate engine through its bounded `qalc` command. A small input
adapter supplies currency units for unlabelled additive amounts, leaving
multipliers, divisors, percentages, and physical unit algebra to Qalculate. File
search reuses Nautilus's `org.gnome.Shell.SearchProvider2` interface and the
existing GNOME LocalSearch index, respecting its indexed folders and exclusions.
It does not build another file index. Directory completion reads only the
specified directory. Emoji and Unicode names reuse installed IBus catalogs;
their derived cache lives in `$XDG_CACHE_HOME/dotfiles/hyprland/`.

Zen bookmarks are read from a private snapshot of the active installation's
default profile, including its SQLite WAL, without changing browser data.
Bookmarks open as new tabs in that profile. Web searches pass the query to Zen
so its own configured engine handles it; browser tab search is not enabled.
Qalculate refreshes cached exchange rates at most daily in the background and
shows their date with every conversion. Offline use keeps the dated cached
rates. ECB reference rates are published on working days, so weekends retain
the latest working day’s date. The native `qalc` executable is preferred. On this Silverblue install,
the package is staged and an unmodified user-local RPM payload under
`~/.local/lib/dotfiles/qalculate/` supplies it until the system executable is
available. Bubblewrap gives that fallback its packaged data directory without
changing the running system's packages.

The capture overlay freezes each monitor and keeps selection and annotation in
the same interface. It covers the floating pill. The icon toolbar appears only
after an area is selected and hides while
the area is being adjusted; there is no top hint. Its tooltips identify Select,
Pen, Arrow, Box, Text, Redact, Undo, cursor toggle, copy/save, and cancel. Choose an ink
color and use Undo or Ctrl+Z. Select lets you reframe the area without leaving
the overlay. The Cursor On/Off button controls whether the pointer appears in
the image or recording. Enter or Ctrl+C exports the annotated image directly to
the clipboard and a PNG in the XDG Pictures directory under `Screenshots/`.
Escape cancels. Selection borders and controls are excluded from the export.
No separate image editor opens, and no additional screenshot shortcuts are bound.

Selections stay within a single monitor. Alt+Print starts with the active
window's visible rectangle selected on its monitor. For recording, choose the
area and cursor option, then press Enter or Record. Press Ctrl+Shift+Alt+R again
to stop, or click the recording indicator on the other monitor. The recorder
receives SIGINT and finalizes an MP4 in the XDG Videos directory under
`Recordings/`. Video dimensions are rounded down to even numbers as required by
the encoder. During recording, both monitors are dimmed outside the selected
rectangle. The rectangle remains live and undimmed; the shading passes clicks
through to applications. Its border sits outside the encoded image. Capture
startup uses parallel raw pixmaps instead of sequential PNG compression and
reuses a preloaded capture worker with its graphics context warmed at login.
The worker has no visible selection window while idle, releases captured images
when finished, and has no layer fade animation. A cold fallback remains available
when the worker is not running.

The clipboard picker preserves text and image bytes and renders previews as
plain text. Cliphist respects selections marked sensitive by the source
application; history otherwise persists in its default cache database.
`cliphist wipe` clears that history.

The lock screen has an opaque background, password entry, and clock on each
display. **Automatic locking is disabled by preference.** There are no idle
timers or automatic lock-on-sleep hooks. Super+L and the power menu provide
manual locking. Startup stops the legacy idle service even if an old lock
verification marker remains.

The persistent Quickshell desktop lives in `hyprland/config/shell/`. The main HP
OMEN (DP-3) has one floating pill, centered 8 pixels below the top edge.
Super+Ctrl+Shift+F toggles its visibility until pressed again. The pill also
hides automatically while its monitor's active workspace has a fullscreen app.
It overlaps applications and reserves no tiling space. The compact pill shows
only the time and EN/RU keyboard layout, with a lit notification dot only while
active notifications remain. There is no separator or inactive dot. Click the time or dot for the calendar and notification
center. Volume/microphone/brightness feedback and workspace changes temporarily
use the pill itself. Notifications appear independently in the top-right corner,
with the same small gap from the top and right edges.

Hover widens the pill to reveal workspaces fixed to its left inset, app tray
icons, media, sound, system statistics, network, Bluetooth, and power
controls. Month, date, and weekday appear
immediately to the left of the stationary clock. A recording indicator appears
while recording, and the sound icon reflects mute state. Leaving collapses it after 240 ms; an open menu or tray menu keeps it
expanded. Media, mixer, system, network, Bluetooth, power, and notifications grow from the
same floating surface, with a constant 20-pixel corner radius and a single
220 ms geometry animation. Popup content retains its size and screen position
through the closing fade; header coordinates stay on whole pixels during morphs.
The pill has a translucent brown gradient without a border, sheen, or outer
shadow. Compositor background blur is restricted to its painted body. Its
background adapts [Ricelin’s PillBody](https://github.com/Gakuseei/Ricelin/blob/main/configs/quickshell/pill/PillBody.qml);
the MIT attribution is retained in `shell/RICELIN-LICENSE.txt`.
The native surface stays fixed while its input region follows the pill, keeping
hover stable and allowing clicks through empty space. Opening a view lets an
outside click dismiss it. The launcher also closes with Escape or a second tap. Losing focus closes
ordinary pill views, including when an application on another monitor gains
focus. The grip at the right of the launcher search field moves it within its
display, keeping the pointer captured until release even during fast movement.
After a real drag, outside clicks and focus loss leave it open; Escape animates
its position and size back into the pill. Every reopening starts with an empty
query and the normal pill placement.
Escape dismisses open views. Every section replaces the entire pill header with
its view, with no close cross in the expanded bar. Header controls hold their
screen positions while fading out, and the workspace highlight stays terracotta
through collapse. Scrollable pill content uses twice the standard wheel step.
Destructive power actions require a second click to confirm.

The media view fits its artwork, title/artist/album, playback controls, and seek
wave without empty space below. The wave moves during playback and rests when
paused. Player selection appears when multiple MPRIS players are available;
the music button disappears and its open view closes when the last player exits.
The mixer controls PipeWire output/input
selection and output and microphone levels/mute.
Search uses compact result rows with icons, names, and secondary descriptions.
All sections use the full surface without the clock header.
Sound has two vertical faders for the output and microphone.
Left-click each bottom icon to toggle mute; right-click it to
choose a device. Device names appear only in that dropdown. Brightness remains on the hardware
keys with feedback in the pill; opening Sound does not query monitor brightness.
Notification cards use subtle glass fills in the center and brown glass for
corner banners. The center keeps the calendar alongside the list without a
dividing line. App groups collapse into stacked previews; individual message
bodies and available actions stay expanded whenever those messages are shown.
Brightness writes are serialized and the most recent requested setting is kept.
The system view samples CPU, GPU, memory, temperatures, VRAM, storage, swap,
network rates, and uptime, with separate labelled 0–100% utilization meters. Its worker runs only
while that view is visible; unavailable sensor readings show a dash. Storage
usage refers to the home filesystem, avoiding Fedora's immutable root image.

Common views preload on first hover and remain cached; other views unload after
two idle minutes. The launcher clears its query on every opening while keeping
its application index and provider caches warm.
The small terracotta marker adapts the idea of [Ricelin's Ame](https://github.com/Gakuseei/Ricelin/blob/main/configs/quickshell/pill/Ame.qml):
one shape pulls out into a dot, jumps in an arc, then unfolds on landing into
the active workspace indicator, notification action background,
launcher caret, slider handle, selected calendar date, notification accent strip,
selected metric value, connection status, Bluetooth thumb/device selection,
and focused power action. It docks beneath each control’s text and replaces its
normal highlight or handle, without an outer glow. Fuzzy matching retains Ricelin's MIT
attribution. Clipboard history remains in its existing standalone picker; there
is no wallpaper view in the pill.

Tap either Super key alone to expand the pill into the application launcher.
Holding Super for 200 ms hides the pill; releasing it immediately restores the
current view. A tap opens the launcher without briefly hiding the pill.
Using another key with Super cancels the tap and hides the pill while the
modifier stays held, preserving existing Super shortcuts. Workspace scrolling,
window dragging, and resizing also cancel the tap. Super+R and Super+Space open
the same integrated launcher when Super is released. Super+M and Super+N likewise
open power and notifications on release. The gesture observer uses Hyprland's Lua
`input.keyboard.key` event, so it does not consume keys or depend on EN/RU layout.
Input timestamps reject late IPC messages so a delayed hide cannot strand the
pill after release. The pill stays available over fullscreen applications.

Panel buttons have no hover highlights or tooltips; icon-button hints are used
for accessibility. Tray menus use the shell's dark colors and typography, with
checks, disabled actions, separators, and navigable submenus. Clickable controls
use a pointer cursor. Bluetooth uses a fixed-height scrolling viewport.
Quickshell uses Adwaita Sans Regular with 18px text, including the compact launcher
and mixer. Typography is defined in `shell/ShellTheme.qml`;
`tools/ShellTheme.qml` links to that shared theme for standalone tools.
Workspaces appear as dim dots with a white active
indicator that stretches to fill a minimum-width block when there are few workspaces.
Click a dot or scroll over the block to switch; the indicator animates between them.
The pill floats above the application, and tiling gaps are zero. Windows have no
compositor borders or shadows; tiled and maximized
windows have square corners, while ordinary floating windows keep rounded
corners. Keyboard focus changes on click; hover and scrolling work on inactive
windows under the pointer. Telegram's media viewer opens directly
fullscreen on Telegram's monitor, without a tiled split or opening animation.
Telegram receives a maximized preview state to preserve its native click-to-close
behavior while Hyprland covers the full monitor. Its intermediate maximize and
remembered fullscreen output requests are ignored.
Window moves and layout resizes use a short easing curve without spring
overshoot. Undersized app frames scale instead of extending their edge pixels
while a window grows, reducing resize smearing while keeping animations.
Shrinking windows can still briefly clip content until the app redraws.
Window fade-in is disabled so windows beneath a fullscreen app
reappear immediately when it closes; opening, closing, panel, and workspace
motion remains animated.
Ethernet and Bluetooth have separate icon buttons and menus. Ethernet shows
connection state, the negotiated Ethernet link capacity, and the last measured
Internet download/upload bandwidth. The refresh icon on the speed row starts an
on-demand transfer test against [Cloudflare's public speed-test endpoints](https://github.com/cloudflare/speedtest).
Only that test animates the refresh button; connection status polls silently.
The test uses synthetic data and bounded parallel transfers, with a small probe
and increasing payload sizes. It measures the current path to Cloudflare, so
results can vary with routing, congestion, VPNs, and other traffic. No bandwidth
test runs automatically. The previous successful result and timestamp are cached
in `$XDG_CACHE_HOME/dotfiles/hyprland/internet-speed.json`, including across restarts;
failed tests keep the previous measurement. Bluetooth scans
while open, placing connected devices first and other devices below a divider.
Click a device to connect or disconnect; a spinner marks pending operations.
Unpaired devices are paired before connection, with failures shown beside the device.
Bluetooth can be enabled or disabled with the menu’s power icon.

The notification center follows the GNOME layout: notifications on the left,
calendar on the right, then events for the selected day and world clocks below it.
Notifications group by app and exact title with stacked previews. The first
card's chevron expands the group; a separate bottom row collapses it. Clicking a
card's cross dismisses that message. Holding the cross for half a second fills a
circle and dismisses its group; leaving the control cancels the hold. Visible
messages show their expanded bodies, available actions, and reply button.
The clear-all icon sits at the bottom right beside Do not disturb.
The calendar uses evenly sized rows and larger navigation arrows, with no Today button
or day-of-week heading. Day highlights are circles inside equally spaced square cells.
Events are cached by date in `$XDG_CACHE_HOME/dotfiles/hyprland/agenda.json`
(normally under `~/.cache`), retaining up to 62 queried days across shell restarts.
Background refresh keeps cached events visible, including cached entries from
individual calendars that are temporarily unavailable.
It reads selected, enabled calendars through Evolution Data Server and reuses
saved GNOME Clocks locations, including settings from its Flatpak. Sections are
omitted when not configured. No calendar accounts or clock locations are added.

The center lists active notifications, with a limit of 100 non-transient entries.
App withdrawals, activation, replies, and dismissal remove active entries;
explicit dismissal and clearing slide cards upward while fading them out, then
close their space smoothly. Surviving cards and their group keep their identity
and expanded state; a collapsed stack reveals its next card beneath the exit.
Banner timeouts hide the banner while retaining the active
entry and its app callbacks in the center. Hovering a banner and then leaving it
consumes that banner too. Transient notifications skip the
center. DND preferences alone are saved in
`$XDG_STATE_HOME/dotfiles/hyprland/notifications.json` (normally under
`~/.local/state`); notification contents are not saved or restored as history.
Critical notifications bypass Do not disturb.
Cards show the notification image, summary, body, app actions, and dismiss
control. Titles are one line with ellipsis. Banner bodies are one line at rest
and expand to at most five lines on hover, revealing actions and inline Reply
when provided by the app. Center bodies are always expanded to at most five lines.
Clicking a live card invokes its default action and removes the entry. Inline
Reply supports Send/Cancel, Enter to send, and Escape to cancel; drafts remain
in memory only, and follow the message into the center when its banner is consumed.
Banners fade and drop in at the top-right with a slight tilt, independently of
the pill. Fresh messages joining a stack fall onto its top card too. Notifications with
the same app and exact title share a stack, showing the newest message and a
count. The arrow expands or collapses its messages; the top dismiss button
closes that banner group. Up to four groups can appear at once.
Banner and center cards use the pill's translucent brown gradient, with lighter
inset surfaces in the center, slim glass stack edges, and banner count badges.
Arrivals queue during banner hover/reply. Opening the center consumes visible and
queued banners; arrivals while it is open go directly into the center. Those
messages, including later updates, do not replay as banners after it closes.
Banner actions reveal in one height animation. Center notifications retain
their order during pointer interaction, and the marker stays on its last target
when the pointer moves through gaps between messages.

Notification arrivals never request keyboard focus. A reply editor requests it
only after an explicit Reply click. Mixer and media controls accept keyboard
navigation after interaction; the launcher requests focus when opened. Outside
clicks and focus loss dismiss ordinary views on either display. A dragged
launcher stays open until dismissed explicitly and does not intercept outside
clicks. Secondary displays have no input shield.

Volume feedback watches PipeWire directly, including changes made by keyboard
keys, Logitech mouse gestures, and other applications. Speaker/microphone mute
changes stretch the same pill to the right with a compact, thick progress bar,
clearing after 1.6 seconds. Brightness uses the same progress bar; workspace
switches stretch the pill to the left with the animated workspace indicator.
The clock stays visible and stationary. The Quickshell Polkit agent presents system authorization
requests with masked password entry, retry feedback, and Escape to cancel.
Passwords are cleared on submission and when the authentication request changes.

The power menu has two rows of icon buttons (lock/suspend, then logout/restart/shutdown),
with no title or close cross. Click its panel icon again to close it.
It asks for a second click before logout, restart, or shutdown.
Shell colors are centralized in `ShellTheme.qml`; bundled Lucide SVG controls
include their license in `shell/icons/LICENSE.txt`.

Manual locking uses the transient `dotfiles-hyprland-lock.service`; clipboard
watchers use `dotfiles-hyprland-clipboard-text.service` and
`dotfiles-hyprland-clipboard-image.service`; the desktop uses
`dotfiles-hyprland-shell.service`; the warmed capture UI uses
`dotfiles-hyprland-capture.service`. Inspect these with `systemctl --user status`
and `journalctl --user -u SERVICE`. They are recreated at login and have no
permanent enablement links. Recording uses the transient
`dotfiles-hyprland-record.service`. These services stop with the UWSM graphical
session and restart on failure. Only one notification daemon and Polkit agent
should run in the session. The shell requires Quickshell 0.3.2 or newer.

<h2 align="center">
  <p>System sleep</p>
</h2>

`services/sleep/` restricts normal systemd suspend to deep (S3) sleep using
`SuspendState=mem` and `MemorySleepMode=deep`. If that attempt fails, systemd
stops instead of trying the `freeze` / `s2idle` fallback. Requires systemd 256+
and hardware with deep sleep support; this is the configuration for the
TUF GAMING B650-PLUS desktop with AMD graphics.

On October 6, 2026, a pending wake event interrupted deep sleep. Both GPUs
recovered from that attempt, but the immediate `s2idle` fallback was rejected
by the integrated GPU and left the dedicated Radeon wedged. The original wake
device was not recorded. This configuration removes that fallback; it does not
guarantee recovery from every possible GPU or firmware fault.

The suspend service also enables kernel power-management debug messages and
records wake IRQ information, wake-source counters, suspend statistics, interrupt
mapping, and USB / ACPI wake settings before and after each attempt. Diagnostics
are saved in the system journal, time-limited to five seconds per hook, and
cannot block sleep on failure. Kernel PM debug messages remain enabled until
reboot (or until `/sys/power/pm_debug_messages` is set back to `0`).

<h3 align="center">
  <p>Usage</p>
</h3>

From the repository root:

```bash
./services/sleep/manage install
```

The helper installs the two configuration files under `/etc/systemd/` and the
executable under `/usr/local/sbin/`, restores SELinux labels when available, and
reloads systemd. It takes effect on the next sleep attempt without rebooting.
When run from Distrobox, it executes on the host and requests administrator
authentication there. Installation does not trigger sleep.

`_scripts/load` includes this installation. `_scripts/dump` calls
`./services/sleep/manage dump` to save the installed host files back to the repo.

After the next sleep attempt, inspect these logs on the host (use `-b -1`
instead of `-b` if you have rebooted since the attempt):

```bash
journalctl -b -u systemd-suspend.service
journalctl -b -k -g 'PM:|Wakeup|wakeup|amdgpu'
```

To remove this configuration, run on the host:

```bash
sudo rm /etc/systemd/sleep.conf.d/90-deep-only.conf \
    /etc/systemd/system/systemd-suspend.service.d/90-wake-diagnostics.conf \
    /usr/local/sbin/sleep-wake-diagnostics
sudo systemctl daemon-reload
echo 0 | sudo tee /sys/power/pm_debug_messages
```

<h2 align="center">
  <p>Audio outputs (WirePlumber)</p>
</h2>

Custom ALSA profiles keep HDMI / DisplayPort 5 on the OMEN monitor as the
only output on the Navi GPU and make the RØDE PodMic USB input-only. The
PodMic microphone remains available. Alternate GPU outputs, PodMic playback
ports, and the Pro Audio profiles for these two devices are hidden.

The rule targets GPU `alsa_card.pci-0000_03_00.1` and PodMic
`alsa_card.usb-R__DE_R__DE_PodMic_USB_973F4E9B-00`. On another machine, adjust
the device matches and HDMI mapping using `wpctl status` and `wpctl inspect`.
These ALSA rules leave other audio devices unaffected. This uses WirePlumber 0.5 configuration
and PipeWire's user ALSA profile directory (verified with PipeWire 1.6.9).

`52-bluetooth-headphones-only.conf` separately limits Bluetooth audio to A2DP
roles and disables the HFP/HSP backend and automatic headset switching. Bluetooth
headphones retain music playback, while hands-free/headset profiles and their
microphones are unavailable. This applies to all Bluetooth headsets, including
the WH-1000XM5; LE Audio (BAP) roles are also excluded. The USB PodMic remains
available for calls.

<h3 align="center">
  <p>Usage</p>
</h3>

From the repository root, install both profiles before the rules, then reload:

```bash
mkdir -p ~/.config/alsa-card-profile/mixer/profile-sets ~/.config/wireplumber/wireplumber.conf.d
cp ./alsa-card-profile/mixer/profile-sets/{omen-hdmi5-only,podmic-input-only}.conf ~/.config/alsa-card-profile/mixer/profile-sets/ &&
    cp ./wireplumber/wireplumber.conf.d/{51-audio-output-cleanup,52-bluetooth-headphones-only}.conf ~/.config/wireplumber/wireplumber.conf.d/ &&
    systemctl --user restart wireplumber
```

The profile filenames resolve from `~/.config/alsa-card-profile/mixer/profile-sets/`,
so the rule contains no username or absolute home path. `_scripts/load` installs
these files; `_scripts/dump` saves them and normalizes any absolute profile paths.

To restore the available output choices:

```bash
rm ~/.config/wireplumber/wireplumber.conf.d/51-audio-output-cleanup.conf
systemctl --user restart wireplumber
```

To re-enable Bluetooth headset modes separately:

```bash
rm ~/.config/wireplumber/wireplumber.conf.d/52-bluetooth-headphones-only.conf
systemctl --user restart wireplumber
```

<h2 align="center">
  <p>Secret Service</p>
</h2>

Fedora 45 uses the packaged `oo7-daemon` and `pam_oo7`, including for GOA.
`./services/secrets/manage install` ties oo7 to `graphical-session.target` so it
starts on every desktop login and stops on logout even with lingering enabled.
It also restarts oo7 after a clean exit caused by losing D-Bus. `_scripts/load`
installs this setup; `./services/secrets/manage check` verifies it.

GDM's packaged PAM configuration delivers the password at login. D-Bus activation
alone is insufficient for that handoff, so this setup starts oo7 with the session.
A daemon restart can still leave encrypted collections locked: setup does not
retain the login password or preserve oo7's in-memory unlock state. Unlock the
keyring again or log out and back in with a password when that happens.

The Fedora 44 GNOME Keyring build recipe has been retired. Its saved RPMs and
logs remain in `~/.local/state/dotfiles/gnome-keyring/`.

`_scripts/load` also runs `./apps/manage install all` for the pinned Papers,
Bazecor and OpenLogi forks and an upstream wl-screenrec build. See
