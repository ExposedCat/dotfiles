<h2 align="center">
  <p>Hyprland</p>
</h2>

`hyprland/config/` contains the Hyprland 0.57 Lua configuration. The entry point
loads modules for monitors, startup/environment, appearance, input, application
commands, keybindings, and window rules. Edit these repository files, then install:

```bash
./hyprland/manage install
./hyprland/manage check
```

The helper runs on the host when invoked from a container. It validates the
configuration with `Hyprland --verify-config`, stages it alongside the installed
directory, and saves the entire previous `~/.config/hypr/` directory under
`~/.local/state/dotfiles/hyprland/backups/`. Unrelated files in that directory are
preserved during installation. A matching installation is a no-op. It reloads
the running session and restores the previous files if that reload reports an
error. It does not restart Hyprland or install packages. XDG configuration and
state directory overrides are supported.

List backups or restore the most recent pre-install snapshot:

```bash
./hyprland/manage backups
./hyprland/manage rollback
# Restore a specific snapshot using the ID printed by backups:
./hyprland/manage rollback BACKUP_ID
```

Restoring also backs up the configuration it replaces. Backups are local and are
not committed. Rollback restores the whole configuration directory to its saved
state, including unrelated files. No command prunes backups automatically.

The current monitor module matches the OMEN and Dell by description, with the
1080p Dell at approximately 75 Hz centered above the 1440p OMEN at approximately 165 Hz, both
at scale 1. Other monitors use their preferred mode with automatic placement.
UWSM remains the session manager. The startup module creates systemd user
services for text and image clipboard history. These services restart on failure
and stop with `graphical-session.target`. Installing reconciles the services;
reloading the Lua config alone does not launch duplicate processes. A rollback
to the initial configuration stops the added clipboard and idle services.
Appearance retains the packaged defaults, with the autogenerated-config notice
disabled. The package plan is in [hyprland-packages.md](hyprland-packages.md).

Everyday controls:

Keyboard layouts are English (US) and Russian. Caps Lock switches between
them; Shift+Caps Lock toggles normal Caps Lock.

| Shortcut | Action |
| --- | --- |
| Super+Return | Kitty terminal |
| Super+E | New Nautilus window |
| Super+Space or Super+R | Centered application search; type a name and press Enter to launch the first match |
| Super+Q | Close window |
| Super+F | Toggle fullscreen |
| Super+V | Toggle floating window |
| Super+Shift+V | Search clipboard history; Enter copies the selected entry; Escape closes |
| Super+L | Lock with Hyprlock; use your normal login password to unlock |
| Print | Select and annotate a screenshot area |
| Alt+Print | Preselect the current window in the capture overlay |
| Ctrl+Shift+Alt+R | Select a recording area, or stop the active recording |
| Ctrl+Alt+Left/Right | Previous/next occupied workspace, including Logitech side buttons |
| Volume and mute keys | PipeWire volume and mute |
| Play/pause and previous/next keys | Control an MPRIS player, preferring one already playing |
| Brightness keys | Adjust the focused monitor through DDC/CI in 5-point steps |

The Quickshell launcher indexes installed desktop entries, including Flatpaks,
and ranks application-name prefixes before other matches. For example, type
`Tele` and Enter to launch Telegram. UWSM launches the chosen desktop entry.

The capture overlay freezes each monitor and keeps selection and annotation in
the same interface. The toolbar appears only after an area is selected; there
is no top hint. Choose Select, Pen, Arrow, Box, Text, or Redact; choose an ink
color and use Undo or Ctrl+Z. Select lets you reframe the area without leaving
the overlay. The Cursor On/Off button controls whether the pointer appears in
the image or recording. Enter or Ctrl+C exports the annotated image directly to
the clipboard and a PNG in the XDG Pictures directory under `Screenshots/`.
Escape cancels. Selection borders and controls are excluded from the export.
No separate image editor opens, and no additional screenshot shortcuts are bound.

Selections stay within a single monitor. Alt+Print starts with the active
window's visible rectangle selected on its monitor. For recording, choose the
area and cursor option, then press Enter or Record. Press Ctrl+Shift+Alt+R again
to stop, or click the recording indicator on the other monitor. The recorder
receives SIGINT and finalizes an MP4 in the XDG Videos directory under
`Recordings/`. Video dimensions are rounded down to even numbers as required by
the encoder. During recording, both monitors are dimmed outside the selected
rectangle. The rectangle remains live and undimmed; the shading passes clicks
through to applications. Its border sits outside the encoded image. Capture
startup uses parallel raw pixmaps instead of sequential PNG compression, reads
its metadata directly, and has no layer fade animation.

The clipboard picker preserves text and image bytes and renders previews as
plain text. Cliphist respects selections marked sensitive by the source
application; history otherwise persists in its default cache database.
`cliphist wipe` clears that history.

The lock screen has an opaque background, password entry, and clock on each
display. Automatic locking remains disabled until a manual Super+L lock/unlock
check succeeds. After that check, enable the idle service with:

```bash
python3 ~/.config/hypr/tools/desktop.py enable-idle
```

It locks after 10 idle minutes and powers off the screens after 11, respecting
application idle inhibitors. It also requests locking before sleep and waits
for the compositor's lock notification before releasing its sleep inhibitor.
It does not initiate suspend. Changing `hyprlock.conf` invalidates the local
verification marker and pauses the idle service until the new config is checked.
For a nondefault XDG config directory, use its `hypr/tools/desktop.py` path.

Manual locking uses the transient `dotfiles-hyprland-lock.service`; clipboard
watchers use `dotfiles-hyprland-clipboard-text.service` and
`dotfiles-hyprland-clipboard-image.service`; the verified idle service is
`dotfiles-hyprland-idle.service`. Inspect these with `systemctl --user status`
and `journalctl --user -u SERVICE`. They are recreated at login and have no
permanent enablement links. Recording uses the transient
`dotfiles-hyprland-record.service`. The full Quickshell bar, notifications,
and Polkit dialogs are the next stage.

Check the install/restore failure handling with:

```bash
python3 -m unittest discover -s hyprland/tests
```

<h2 align="center">
  <p>LAN hostname resolution</p>
</h2>

`services/mdns/` configures this PC to resolve LAN names such as `server.local`.
The server advertises its own name using the configuration and `setup.sh` in
`ExposedCat/infra`. PC services are managed separately in `ExposedCat/local-infra`.

From this repository on the PC:

```bash
./services/mdns/manage install
./services/mdns/manage check
getent ahostsv4 server.local
ssh kitkat@server.local
```

`_scripts/load` includes installation; `_scripts/dump` captures the two installed
configuration files. The helper runs on the host when called from Distrobox and
requests sudo for installation. It backs up replaced files, enables Avahi, and
configures systemd-resolved and NetworkManager to resolve mDNS names. Existing
active Ethernet/Wi-Fi profiles are set to resolver mode; a NetworkManager default
covers new profiles. It applies the resolver setting without disconnecting links.
Requires the host's Avahi, systemd-resolved, and NetworkManager packages.

NetworkManager's [mDNS resolver mode](https://networkmanager.pages.freedesktop.org/NetworkManager/NetworkManager/nm-settings-nmcli.html)
uses `connection.mdns=1`; Avahi continues to own this PC's name advertisements.
The configuration discovers the server's current address rather than storing
an IP address in `/etc/hosts`.

<h2 align="center">
  <p>System sleep</p>
</h2>

`services/sleep/` restricts normal systemd suspend to deep (S3) sleep using
`SuspendState=mem` and `MemorySleepMode=deep`. If that attempt fails, systemd
stops instead of trying the `freeze` / `s2idle` fallback. Requires systemd 256+
and hardware with deep sleep support; this is the configuration for the
TUF GAMING B650-PLUS desktop with AMD graphics.

On October 6, 2026, a pending wake event interrupted deep sleep. Both GPUs
recovered from that attempt, but the immediate `s2idle` fallback was rejected
by the integrated GPU and left the dedicated Radeon wedged. The original wake
device was not recorded. This configuration removes that fallback; it does not
guarantee recovery from every possible GPU or firmware fault.

The suspend service also enables kernel power-management debug messages and
records wake IRQ information, wake-source counters, suspend statistics, interrupt
mapping, and USB / ACPI wake settings before and after each attempt. Diagnostics
are saved in the system journal, time-limited to five seconds per hook, and
cannot block sleep on failure. Kernel PM debug messages remain enabled until
reboot (or until `/sys/power/pm_debug_messages` is set back to `0`).

<h3 align="center">
  <p>Usage</p>
</h3>

From the repository root:

```bash
./services/sleep/manage install
```

The helper installs the two configuration files under `/etc/systemd/` and the
executable under `/usr/local/sbin/`, restores SELinux labels when available, and
reloads systemd. It takes effect on the next sleep attempt without rebooting.
When run from Distrobox, it executes on the host and requests administrator
authentication there. Installation does not trigger sleep.

`_scripts/load` includes this installation. `_scripts/dump` calls
`./services/sleep/manage dump` to save the installed host files back to the repo.

After the next sleep attempt, inspect these logs on the host (use `-b -1`
instead of `-b` if you have rebooted since the attempt):

```bash
journalctl -b -u systemd-suspend.service
journalctl -b -k -g 'PM:|Wakeup|wakeup|amdgpu'
```

To remove this configuration, run on the host:

```bash
sudo rm /etc/systemd/sleep.conf.d/90-deep-only.conf \
    /etc/systemd/system/systemd-suspend.service.d/90-wake-diagnostics.conf \
    /usr/local/sbin/sleep-wake-diagnostics
sudo systemctl daemon-reload
echo 0 | sudo tee /sys/power/pm_debug_messages
```

<h2 align="center">
  <p>Audio outputs (WirePlumber)</p>
</h2>

Custom ALSA profiles keep HDMI / DisplayPort 5 on the OMEN monitor as the
only output on the Navi GPU and make the RØDE PodMic USB input-only. The
PodMic microphone remains available. Alternate GPU outputs, PodMic playback
ports, and the Pro Audio profiles for these two devices are hidden.

The rule targets GPU `alsa_card.pci-0000_03_00.1` and PodMic
`alsa_card.usb-R__DE_R__DE_PodMic_USB_973F4E9B-00`. On another machine, adjust
the device matches and HDMI mapping using `wpctl status` and `wpctl inspect`.
These ALSA rules leave other audio devices unaffected. This uses WirePlumber 0.5 configuration
and PipeWire's user ALSA profile directory (verified with PipeWire 1.6.9).

`52-bluetooth-headphones-only.conf` separately limits Bluetooth audio to A2DP
roles and disables the HFP/HSP backend and automatic headset switching. Bluetooth
headphones retain music playback, while hands-free/headset profiles and their
microphones are unavailable. This applies to all Bluetooth headsets, including
the WH-1000XM5; LE Audio (BAP) roles are also excluded. The USB PodMic remains
available for calls.

<h3 align="center">
  <p>Usage</p>
</h3>

From the repository root, install both profiles before the rules, then reload:

```bash
mkdir -p ~/.config/alsa-card-profile/mixer/profile-sets ~/.config/wireplumber/wireplumber.conf.d
cp ./alsa-card-profile/mixer/profile-sets/{omen-hdmi5-only,podmic-input-only}.conf ~/.config/alsa-card-profile/mixer/profile-sets/ &&
    cp ./wireplumber/wireplumber.conf.d/{51-audio-output-cleanup,52-bluetooth-headphones-only}.conf ~/.config/wireplumber/wireplumber.conf.d/ &&
    systemctl --user restart wireplumber
```

The profile filenames resolve from `~/.config/alsa-card-profile/mixer/profile-sets/`,
so the rule contains no username or absolute home path. `_scripts/load` installs
these files; `_scripts/dump` saves them and normalizes any absolute profile paths.

To restore the available output choices:

```bash
rm ~/.config/wireplumber/wireplumber.conf.d/51-audio-output-cleanup.conf
systemctl --user restart wireplumber
```

To re-enable Bluetooth headset modes separately:

```bash
rm ~/.config/wireplumber/wireplumber.conf.d/52-bluetooth-headphones-only.conf
systemctl --user restart wireplumber
```
